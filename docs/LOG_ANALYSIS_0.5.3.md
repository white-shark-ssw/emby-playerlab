# 0.5.2 真机日志分析与 0.5.3 修复

样本：2026-08-02，Item 63368，传输层 AVPlayer。

## 日志结论

1. 起始主连接正常达到约 25 MB/s，但随后长期下降到约 3.3–4.2 MB/s；退出时全会话平均约 4.4 MB/s。
2. 多数双击 Seek 的真实新画面耗时仍为约 65–100 ms，说明本地 HTTP、Range 和画面定位基本正常。
3. 远距离拖动到 449 秒与 574 秒时，紧急区间尚未完整到达，恢复时间分别约 1.3 秒和 0.8 秒。
4. 日志没有出现 Stall 恢复记录。根因不是 Watchdog 完全失效，而是 AVPlayer 的瞬时 `.paused` 状态把 `snapshot.isPlaying` 改为 false，使 Watchdog 和下一次 Seek 都误以为用户已经暂停。
5. v0.5.2 已避免主线程被历史 Range 反复迁移；本次低速主要表现为同一条 115 长连接运行一段时间后吞吐下降。

## 0.5.3 处理

- 以 `shouldPlayWhenReady` 保存用户播放意图，不再用 `timeControlStatus == .playing` 作为唯一播放状态。
- Seek generation 只允许最新一次 Seek 恢复播放。
- 引擎位置只由真实周期时间或新画面推进，不再在 Seek 提交瞬间伪造目标位置。
- Seek 提交、完成和短延迟复查都执行续播；用户主动暂停时所有自动续播均退出。
- 传输层 Watchdog 在约 4 秒无位置/缓冲增长时启动恢复。
- 115 不建立额外探测连接；持续 4 秒低于自适应阈值后，在当前游标处重建单主连接。
