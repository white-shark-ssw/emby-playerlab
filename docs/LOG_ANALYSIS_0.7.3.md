# 0.7.2 真机日志分析与 0.7.3 修复依据

测试媒体：Item 63368，约 996 MB，时长约 609.943 秒。

## 下载速度

0.7.2 的 KTV 预取器创建单条 `bytes=0-996085873` 请求。第一次播放中，App 自有传输指标长期约为 0.7–1.6 MiB/s，低于或接近媒体平均消耗速度，因此缓存尾部经常被播放追上。

AVPlayer AccessLog 在第二次播放显示的数百 Mbps 或数 Gbps，是 localhost KTV 代理向 AVPlayer 交付本地缓存的速率，不是 115/CDN 上游速率。0.7.3 继续只以缓存文件真实新增字节计算上游下载速度。

## 画面停止、声音继续

第二次播放 Seek 到约 303.425 秒后，关闭时播放时钟已推进到约 313.875 秒，说明音频与播放器时间轴仍在前进。与此同时 AccessLog Stall 计数从 2 持续增加到 24，符合视频轨停止产出新画面、音频继续播放的现象。

原看门狗只检测 `currentTime` 是否增长，因此会被继续推进的音频时钟误判为正常。0.7.3 使用 `AVPlayerItemVideoOutput` 独立记录最后一个实际 PixelBuffer，并在音频时钟继续但视频帧超过阈值未更新时执行同引擎恢复。
